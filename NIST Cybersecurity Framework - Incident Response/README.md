# NIST Cybersecurity Framework - Incident Response

## Project Overview

This project demonstrates the application of the National Institute of Standards and Technology (NIST) Cybersecurity Framework (CSF) to analyze and respond to a network security incident involving an ICMP Flood Denial-of-Service (DoS) attack.

The project follows the five core NIST CSF functions—Identify, Protect, Detect, Respond, and Recover—to evaluate the incident, assess organizational risk, and recommend security improvements that strengthen network resilience.

---

## Scenario

A multimedia company experienced an ICMP Flood DoS attack that disrupted internal network services for approximately two hours. The investigation determined that the attacker exploited an unconfigured firewall, allowing excessive ICMP traffic to overwhelm the organization's network infrastructure.

The incident response team restored critical services, investigated the root cause, and implemented additional security controls to reduce the likelihood of future attacks.

---

## Objectives

- Analyze the cybersecurity incident using the NIST Cybersecurity Framework.
- Identify the root cause and affected systems.
- Recommend security controls to improve network protection.
- Develop strategies for incident detection, response, and recovery.
- Demonstrate structured cybersecurity incident reporting.

---

## Framework Applied

This project follows the five core functions of the **NIST Cybersecurity Framework (CSF)**:

### Identify
- Determined that the organization experienced an ICMP Flood Denial-of-Service attack.
- Identified the firewall configuration weakness that allowed the attack.
- Assessed affected systems and business impact.

### Protect
- Recommended firewall hardening and ICMP rate limiting.
- Proposed source IP verification and stronger network security controls.
- Improved security policies and preventive measures.

### Detect
- Enhanced continuous network monitoring.
- Recommended IDS/IPS deployment.
- Improved detection of abnormal ICMP traffic patterns.

### Respond
- Contained the incident by blocking malicious ICMP traffic.
- Restored critical network services.
- Documented the incident and recommended improvements to future response procedures.

### Recover
- Restored affected services.
- Verified normal network operations.
- Recommended continuous monitoring and regular security reviews to improve resilience.

---

## Key Findings

- The attack exploited an improperly configured firewall.
- ICMP flood traffic overwhelmed network resources.
- Internal services became unavailable for approximately two hours.
- Improved monitoring and firewall configuration significantly reduce future risk.
